================================================================
 MODULE FORGE - HOW TO MAKE CUSTOM MODULES WITH JSON
================================================================

Module Forge is a SEPARATE mod from Weapon Forge. It lets you create
custom MODULES - the small grid upgrades you attach to your ship or
weapons (like Health Up, or +Firerate, or Extra Projectile). Custom
modules can drop from crates/bosses and/or be bought in the shop.

No programming needed: the DLL does the work; the JSON files are the
modules. Every *.json in the "modules" folder (next to ModuleForge.dll
in BepInEx\plugins) becomes a module.

----------------------------------------------------------------
 1. HOW IT WORKS
----------------------------------------------------------------

At game startup, Module Forge reads each modules/*.json, clones a
stock module of the right kind as a shell, swaps in your effects, and
registers it so it works with save/continue. It then makes the module
available in loot and/or the shop per your settings.

Edits are read at STARTUP - restart the game to see changes.

A module attaches to ONE of two places, chosen by "target":
  ship    -> the ship-body grid (stat ups, regen, shields, drains)
  weapon  -> a weapon/gadget grid (fire rate, projectiles, explosions)
The game routes it automatically based on this choice.

----------------------------------------------------------------
 2. QUICK START
----------------------------------------------------------------

  1. Install ModuleForge.dll in BepInEx\plugins (its own folder).
  2. Run the game once - a "modules" folder appears next to the DLL
     with example files + a README.
  3. Easiest: open "Module Builder.html", design a module, click
     SAVE .JSON FILE, and drop it in the modules folder.
  4. Restart the game. The module now drops / is in the shop.

Errors are logged to <game>\BepInEx\LogOutput.log (search
"ModuleForge") - a bad file is skipped, never crashes the game.

----------------------------------------------------------------
 3. FILE STRUCTURE
----------------------------------------------------------------

{
  "name": "GlassCannon",        <- REQUIRED, unique id, no spaces
  "displayName": "GLASS CANNON",
  "description": "...",
  "target": "weapon",           <- "ship" or "weapon" (default ship)
  "icon": "HUD_GridTiles_10",   <- module icon sprite (section 6)
  "color": "#ff5555",           <- icon tint: game color or #hex
  "source": "both",             <- "loot" / "shop" / "both" / "none"
  "shopPrice": 150,             <- shop cost in money
  "shopPriceIncrement": 500,    <- added per purchase (0 = fixed price)
  "shopUnlockLevel": 2,         <- stations to unlock first (0 = first)
  "lootWeight": 10,             <- drop chance vs other modules
  "effects": [ ...one or more effect objects... ]   <- REQUIRED
}

A module can carry SEVERAL effects, and you can MIX buffs and debuffs
(e.g. +1 projectile AND -20% fire rate). Just list them all in
"effects".

----------------------------------------------------------------
 4. VALUES
----------------------------------------------------------------

Any magnitude can be a plain number (flat, e.g. "value": 1) or a
scaling object that grows with module level:
    { "baseValue": 2, "increaseMethod": "Add", "change": 1 }
Flat numbers are simplest and level-independent. NEGATIVE numbers are
allowed and do the opposite (e.g. -0.2 fire rate = -20%).

----------------------------------------------------------------
 5. EFFECTS
----------------------------------------------------------------

SHIP effects (use with "target": "ship"):
  ModifyResourceCapacity  { resource, amount }        +/- a tank's max
  ResourceAutoChargeEffect{ resource, amount }        regen per second
  DrainResourceEffect     { resource, amount }        drain/sec (neg=gain)
  AddShieldEffect         { resource, amount }        shield; 0.5 = 50%

WEAPON effects (use with "target": "weapon"):
  ModifyWeaponProperty { targetProperty, deltaCalculationMode, value }
     targetProperty: FireRate, BurstSize, BurstDelay, ProjectileCount,
       Spread, AngleVariance, AngleOffset, KnockbackForce, Cost, Range,
       Speed  (Damage is intentionally unavailable - a game bug)
     deltaCalculationMode:
       "Constant"     flat +value  (e.g. +1 projectile)
       "FromOriginal" +value * base stat  (0.25 = +25%)
       "FromCurrent"  +value * current stat
  IncreaseExplosionRadiusEffect { increaseAmount }
  AddImpactExplosionEffect      { }        projectiles explode on hit
  AddBurnEffect        { amount, costPerProjectile, costResource }
  BurnTickRateEffect   { ticksPerSecond }
     Speeds up how fast BURN ticks on enemies. ticksPerSecond is added to
     the burn tick FREQUENCY while this module is equipped, and stacks
     additively across equipped copies. e.g. burn normally ticks ~1/sec;
     two +0.1 modules make it tick ~1.2/sec (so ~1.2x burn damage/sec).
     - Affects ENEMIES only: burn that enemies put on YOU still ticks at
       the normal rate.
     - This effect does NOT add burn on its own - pair it with a burn
       source (AddBurnEffect, or a burn weapon).
     - Hard-capped so stacking can't run away - see the cap note below.
  BurnColorEffect      { color } OR { rgb: true, rgbSpeed }
     Recolors the BURN FLAMES on enemies while equipped.
       color          a game color name (ColorBlue, ColorPurple...) or #hex.
       rgb            true = ignore color and cycle a rainbow over time.
       rgbSpeed       rainbow speed, hue cycles/sec (default 0.5). rgb only.
       includeTerrain true = ALSO recolor burning terrain/world fire, not
                      just enemies (default false).
     - Your OWN on-fire flames are NEVER recolored (only enemies, plus
       terrain if includeTerrain is on). Like the tick rate, it does NOT
       add burn - pair with a burn source. If several are equipped, the
       most recent one wins (its color AND its includeTerrain setting).
  AddExplosionEffect   { damageType, damageAmount, costPerProjectile,
     costResource, addImpactExplosion, addTimeoutExplosion,
     explosionRadiusIncrement, burn }
  AddDischargeEffect   { chainLengthIncrement, damageIncrement, impact,
     timeout, costPerProjectile, costResource }     the "spark" arc
  Phasing              { }
     While equipped, your PROJECTILES pass through terrain (walls) but
     still hit enemies. No params. (Projectile weapons; for a phasing
     laser use Weapon Forge's per-weapon phasing flag.)
  PierceCap            { pierceCap, falloff, explodeOnLimit }
     While equipped, turns PIERCING on for your projectiles and caps it:
     they pierce THROUGH pierceCap enemies, then vanish on the next
     contact (that enemy still takes the hit). Caps STACK if you equip
     several. Options:
       pierceCap       enemies pierced before it vanishes (default 2)
       falloff         damage lost per enemy pierced (0.2 = -20% each)
       explodeOnLimit  explode when it hits the cap
     (Projectile weapons only.)

  WHERE THE NUMBERS SHOW UP
  Hovering the MODULE (on your ship grid) shows what THAT module adds -
  "PIERCE +2" (and, while installed, the running ship total as old > new),
  or "PHASING ON". Hovering the WEAPON shows the COMBINED total for that
  weapon - "PIERCE 4" / "PHASING ON" - adding the weapon's own built-in
  pierce (Weapon Forge "pierceLimit") to every equipped pierce module.
  NOTE: the game only draws effect lines for a module that's on the SHIP
  GRID - a module sitting in the SHOP list shows just its name/description
  (that's stock behavior, all modules are like that).

The burn/explosion/discharge effects only fire on PROJECTILE weapons.
Keep weapon stats sane: ProjectileCount/BurstSize should end >=1,
FireRate stays >0, Spread >=0 (it clamps).

Resource names: Health, Stamina, Caps, Electron, Fuel, Gel, Tech.
(Money is currency - not usable as a module resource.)

BURN TICK-RATE CAP
------------------
Burn can never tick faster than a set number of times per second, no
matter how many BurnTickRateEffect modules you stack. The cap defaults
to 100 ticks/sec and lives in the BepInEx config file
(BepInEx\config\com.andy.moduleforge.cfg) under [Burn] MaxTicksPerSecond -
edit it there and restart to change the ceiling. (The game can only tick
burn once per frame, so a cap above your frame rate just means "every
frame".)

----------------------------------------------------------------
 6. ICONS & COLOR
----------------------------------------------------------------

Icons are module sprites named "HUD_GridTiles_NN". Handy ones:
  Stat Up 12  Regen 17  Shield 34  Extra Projectile 10  Fire Rate 4
  Spread 5  Projectile Speed 15  Range 11  Burn 40  Explosion 39
  Spark 41  Power Core 18   Burst = "HUD_Modules_17"
The Module Builder page has a dropdown for these.

color: a game ColorAsset name (ColorWhite / ColorOrange / ColorPurple
/ ColorBlue / ColorRed / ColorYellow / Color Tech / ColorPower) OR a
hex value like "#ff5555" (a new color is made on the fly).

----------------------------------------------------------------
 7. AVAILABILITY
----------------------------------------------------------------

source:
  "loot"  only from crates/bosses (default)
  "shop"  only in the shop
  "both"  both
  "none"  NEVER offered - no drops, no shop. The module is still built and
          registered, so it is handy for parking a definition, or for
          testing something without it cluttering your runs.
shopPrice        cost in money (default 100)
shopPriceIncrement  how much is ADDED to the price every time the module
                 is bought (default 0 = the price never changes).

                 HOW THE GAME DOES IT: PUNK escalates repeat purchases by
                 adding a FLAT amount each time - it is NOT a percentage
                 and it does not compound. A module priced 300 with an
                 increment of 500 costs 300, then 800, then 1300, 1800...
                 Real values from the game's own shop table:
                   Fire rate / Proj speed / Spread / Burst / Range
                                            300  then +500 each buy
                   Extra projectile         2500 then +1500 each buy
                   Add Health               200  then +500 each buy
                   Add Fuel / Add Stamina   200  then +400 each buy
                   Power core / Regen       1000 then +1000 each buy
                   Shields                  4000-5000 then +1000 each buy
                 Most one-off modules simply leave the increment at 0.

                 NOTE: the game only re-stocks and re-prices an item that
                 is flagged repeatInShop, so setting an increment turns
                 repeatInShop on for you (unless you set it yourself).
shopPricePercent friendlier way to say the same thing: the increment as a
                 share of the base price. 167 on a 300 module = +500 per
                 buy, matching the stock stat modules. Ignored if
                 shopPriceIncrement is set.
shopUnlockLevel  how many STATIONS you must unlock before it can appear
                 in the shop (default 1; 0 = the very first shop).
                 PUNK gates the shop by station count.
lootWeight       drop chance vs other modules in the same crate pool
                 (default 10; stock modules sit around 10).

Custom modules are registered at startup, so save/continue works.
Note: each shop tier rolls once as you pass it - to see a new shop
module, start a fresh run.

----------------------------------------------------------------
 8. EXAMPLES
----------------------------------------------------------------

Weapon module - glass cannon (more shots, slower fire):
  {
    "name": "GlassCannon", "displayName": "GLASS CANNON",
    "target": "weapon", "source": "both",
    "shopPrice": 150, "shopUnlockLevel": 2,
    "effects": [
      { "type": "ModifyWeaponProperty", "targetProperty": "ProjectileCount",
        "deltaCalculationMode": "Constant", "value": 1 },
      { "type": "ModifyWeaponProperty", "targetProperty": "FireRate",
        "deltaCalculationMode": "FromOriginal", "value": -0.2 }
    ]
  }

Ship module - tanky but leaky:
  {
    "name": "TankPlating", "displayName": "TANK PLATING",
    "target": "ship", "source": "loot",
    "effects": [
      { "type": "ModifyResourceCapacity", "resource": "Health", "amount": 6 },
      { "type": "DrainResourceEffect", "resource": "Fuel", "amount": 0.5 }
    ]
  }
